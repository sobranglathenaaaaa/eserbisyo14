# Frontend UX Simplification Plan - 29-03-1158pm

## Executive Direction

The current interface communicates a lot, but it asks users to read too much before they can act.
The goal is to shift from text-heavy screens to action-first screens.

Primary outcome:
- Users can complete core tasks with less reading, fewer decisions, and lower cognitive load.

Design principle:
- Show less by default, reveal details only when needed.

---

## Problem Statement

Observed risk:
- Dense copy in navigation, cards, and helper text slows scanning.
- Repeated instructional text competes with key actions.
- Important states (urgent, pending, complete) are not visually dominant enough compared with body copy.

UX impact:
- Slower time-to-action.
- Higher chance of missed updates.
- Users feel overwhelmed, especially on first use and on mobile.

---

## Objectives

1. Reduce visible text volume on key pages by 35 to 50 percent.
2. Improve first-click success on top resident tasks (requests, queue, tracking).
3. Make status and next actions understandable in under 5 seconds.
4. Preserve clarity for low-digital-literacy users through plain language and progressive disclosure.

---

## UX Strategy

### 1) Content Hierarchy Reset

Apply a strict copy hierarchy per screen:
- One primary heading.
- One short supporting sentence (max 12 words).
- One primary action.
- Optional secondary action.
- Contextual help hidden behind "Learn more" or tooltip/drawer.

Rules:
- Remove duplicate descriptions that restate labels.
- Replace paragraph guidance with short labels and examples.
- Use verbs for action text: "Track Request", "Join Queue", "Upload ID".

### 2) Progressive Disclosure

Default state shows essentials only:
- Summary metrics.
- Current status.
- Next best action.

Secondary details move into:
- Expandable rows.
- Slide-over panels.
- Contextual tooltips.

### 3) Action-First Layouts

For dashboard and workflow pages:
- First row: "What needs your attention now".
- Second row: Active items only.
- Third row: History and reference content.

Avoid top-heavy hero text blocks on transactional pages.

### 4) Language Simplification Standard

Content style guide:
- 6th to 8th grade reading level.
- Maximum 14 words per sentence in UI copy.
- Prefer concrete nouns and direct verbs.
- Avoid jargon where plain alternatives exist.

Examples:
- "Submit document requests and permits" -> "Request a document"
- "Legacy view of request timeline" -> "Request history"
- "Currently moving through review or processing" -> "In review"

### 5) Visual Priority Over Explanatory Text

Encode meaning with UI elements before text:
- Status chips with color + icon + 1 to 2 words.
- Alert levels with clear severity styling.
- Empty states with one sentence and one action button.

### 6) Navigation Compression

Sidebar improvements:
- Keep category labels short.
- Reduce each item to title + optional badge.
- Show long descriptions on hover/focus only (desktop).
- On mobile, show title only in drawer list.

### 7) Mobile-First Content Budget

Set strict per-component text budgets:
- Card title: max 32 characters.
- Card description: max 60 characters.
- Alert body: max 80 characters.
- Button labels: max 18 characters.

If copy exceeds budget, truncate with "More" interaction.

## Page-by-Page Simplification Plan

### Resident Dashboard

Current issue:
- Large welcome and explanatory blocks compete with task cards.

Plan:
- Keep greeting to one line only.
- Replace "What you can do here" text cards with 3 compact quick actions.
- Merge overview metrics into one clear "Today" strip.
- Convert long alert text into short severity + action CTA.

### Requests and Request History

Current issue:
- Too much descriptive text around statuses and timelines.

Plan:
- Use concise status chips (Draft, In Review, For Pickup, Needs Action).
- Hide detailed timeline by default; reveal per request row.
- Promote "Next required step" as the main line.

### Queue

Current issue:
- Queue explanations can be read-heavy during high-stress moments.

Plan:
- Prioritize queue position, wait estimate, and next action.
- Move queue process explanation into optional help panel.

### OCR and Incident Reporting

Current issue:
- Instructional text likely exceeds practical need.

Plan:
- Use stepper pattern with short step labels.
- Show one instruction per step.
- Replace dense instructions with inline examples.

---

## Interaction and Component Guidelines

1. Buttons
- One primary button per section.
- Avoid descriptive sentence-like button text.

2. Cards
- Headline + key value + one action.
- No multi-paragraph body text.

3. Tables and lists
- Keep row text short.
- Use badges and icons for status.
- Expand for full details on demand.

4. Alerts
- Format: Severity + issue + next action.
- Example: "Needs Action: Correct 1 request. Review now."

5. Empty states
- One sentence only + one CTA.
- Remove generic motivational filler.

---

## Implementation Roadmap

### Phase 1: Content Audit and Prioritization (Week 1)

Deliverables:
- Full UI copy inventory by route and component.
- Redundancy map (remove, shorten, or hide).
- Approved content budget per component type.

Success gate:
- Every screen has a defined primary action and text budget.

### Phase 2: IA and Wireframe Compression (Week 2)

Deliverables:
- Low-fidelity wireframes focused on action-first structure.
- Progressive disclosure map for hidden/expanded content.
- Mobile-first variants for each critical screen.

Success gate:
- Core tasks completable with minimal scrolling and minimal reading.

### Phase 3: UI Refactor Plan and Copy Rewrite (Week 3)

Deliverables:
- Component-level rewrite list (titles, labels, alerts, helper text).
- Standardized status language dictionary.
- Final UX writing guide for consistency.

Success gate:
- No repeated instructional copy across screens.

### Phase 4: Validation and Optimization (Week 4)

Deliverables:
- Usability test with resident and staff personas.
- Metrics report against baseline.
- Final simplification backlog for follow-up sprint.

Success gate:
- Measurable improvement in task completion speed and comprehension.

---

## Measurement Framework

Track before and after:
- Time to first meaningful action.
- Task completion rate for request, queue, and tracking flows.
- Misclick/error rate on key actions.
- Scroll depth on dashboard and request pages.
- User-reported ease-of-use score.

Target improvements:
- 20 percent faster task starts.
- 15 percent increase in successful first attempt completions.
- 25 percent reduction in support-triggering confusion points.

---

## Governance and Quality Controls

1. Introduce a Copy Review Checklist for every new UI change.
2. Enforce text budgets in design review before development.
3. Block merges for new screens that exceed content density standards.
4. Maintain a living UX writing glossary for labels and statuses.

---

## Final Recommendation

Treat "too much text" as a product-level usability issue, not a cosmetic issue.
Prioritize simplification in the next sprint as a direct investment in task success, trust, and adoption.

This plan intentionally focuses on reducing cognitive load while preserving clarity for public-service workflows.
